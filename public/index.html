    Public scientific tooling · SDD control surface. Human + Gemini drive hop / suddenFreq / autoroute through this app (discover → model → plan → execute) — not speaker knobs alone. No street addresses or study-site PII. Telemetry is device metrics only. Hold / Manual freezes autoroute param patches so humans keep the knobs. Patches poll /patch.json mock offline, or ?patch= / ?telemetry= for a live GCP ingest — browser never embeds Gemini keys.
    Incoherent multi-node fleet. Default: two phones, each paired 1:1 via iPhone native Bluetooth (system audio route to a Soundcore — not Web Bluetooth), transmitting at once. Optional third node may be chair-mounted for accel / structure-borne bias. Schedules are independent per tab (Math.random; no shared seed). Listen is optional loopback/debug only.
    Algorithms. hop = incoherent frequency hop (default). am_gate/pulse = AM gated carrier. shriek/shriek_chirp = short upward chirp bursts. Contour-mirrors (generative, not recordings): cry_mirror = irregular pitch glides + sob AM; siren_mirror = two-tone / rising–falling sweep; death_metal_mirror = harsh saw/square + blast-beat AM + detuned drone/shriek. Extreme/burst rotation can pick shriek family or these mirrors. With Vib auto, physical accel prefers pulse/shriek; acoustic mic energy prefers pulse/hop. Debounced ≥300 ms. Hold / Manual freezes remote patches. Default output is 100% Web Audio gain (max practical); BT/hardware still limit SPL.
    Soundcore 2 ultrasonic warning. Anker lists 12 W dual neodymium drivers, BassUp + DSP, IPX7, 5 200 mAh / 24 h, Bluetooth 5.0 — no frequency-response curve published. BT codecs (SBC/AAC) and speaker DSP will likely crush or erase 17–23 kHz carriers. See SPEC.md.
    iPhone / Chrome iOS / Safari (WebKit). Add to Home Screen for a full-screen app. Tap Arm sensors or Signal on to unlock Web Audio and request mic, DeviceMotion, DeviceOrientation (and Ambient Light if present — often na on iOS Chrome). Use volume buttons — silent switch does not mute Web Audio on modern iOS, but hardware + BT absolute volume still cap SPL. Prefer HTTPS (this Vercel deploy). Fleet power: continuous 120 V AC (phones + speakers charging) — Low Power Mode off for dedicated runs. Optional 10–20 Hz TX is hardware-gated (Soundcore/A2DP usually na; phone speaker may pass).
    Over-air needs the browser's cleanup turned off. Echo cancellation, noise suppression and auto gain control all assume they are handling speech, and all three will destroy a 20 kHz carrier — the capture request explicitly disables them. Microphone access also needs a secure context (HTTPS), which this deploy provides.
    Both ends must run at 48 kHz to reach the top of the band. A capture device at 44.1 kHz tops out at 22 050 Hz, and many laptop mics roll off hard above 18 kHz regardless of sample rate. If the decode fails, narrow the band downward before assuming the link is broken — the green input trace on the spectrum plot shows exactly how much of the band survived the trip. Raising symbol duration also buys margin, which is why the default moved to 200 ms; over-air is far less forgiving than loopback.
    The phrase is carried as tones, not as speech. Speech identity lives in formant ratios spanning roughly 100 Hz to 8 kHz — an 80:1 range. 17 500 to 21 000 Hz is a 1.2:1 range, so no transposition of a voice survives the move. Every character gets its own frequency instead, and the receiver quantises each detected tone back to the nearest slot in that plan.
