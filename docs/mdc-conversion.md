# Cursor `.mdc` → Claude Code conversion

`scripts/mdc_convert.py` keeps Cursor project rules and Claude Code memory in sync from **one source of
truth: the `.mdc` files**. Both editors then apply the same guidance; nothing is hand-copied.

## Formats (verified 2026-09-08)

| Editor | Location | Frontmatter | Source |
|--------|----------|-------------|--------|
| Cursor | `.cursor/rules/**/*.mdc` (nested dirs allowed), legacy `.cursorrules` | `description`, `globs`, `alwaysApply` | Context7 `/websites/cursor` → https://cursor.com/docs/rules |
| Claude Code memory | `CLAUDE.md` (root or `.claude/`) | none; supports `@path` imports | Context7 `/websites/code_claude` → https://code.claude.com/docs/en/memory |
| Claude Code rules | `.claude/rules/*.md` | `paths:` list of globs (loads only when a matching file is read; no `paths` → loads at launch) | same |
| Claude Code skills | `.claude/skills/<name>/SKILL.md` | `name`, `description` (auto-loaded when the prompt matches; `/name` invokes) | https://code.claude.com/docs/en/slash-commands |

Cursor's frontmatter is not strict YAML (`globs: *.ts, **/*.tsx` is common and `*` is a YAML alias
marker), so the converter uses a tolerant subset parser on purpose.

## Mapping

| `alwaysApply` | `globs` | `description` | Cursor type | Target |
|---|---|---|---|---|
| `true` | any | any | Always | managed block in `CLAUDE.md` under `<!-- mdc:managed-section -->` |
| `false` | set | any | Auto Attached | `.claude/rules/<slug>.md` with `paths:` = globs |
| `false` | unset | set | Agent Requested | `.claude/skills/<slug>/SKILL.md` (`agent_requested_as: "rule"` in config to emit an unconditional rule instead) |
| `false` | unset | unset (or no frontmatter) | Manual | `.claude/skills/<slug>/SKILL.md`, description `Manual Cursor rule <slug>; invoke with /<slug>` |
| any | any | any | listed under `"spec"` in `.mdc-convert.json` | managed block in `SPEC.md` |

- Nested `pkg/.cursor/rules/x.mdc`: globs are prefixed with `pkg/`; a nested `alwaysApply` rule becomes a path rule on `pkg/**`.
- Sources outside the repo (a shared `/Users/machine/apps/.cursor/rules`) are supported with `--src ../.cursor/rules` or `"sources"` in the config; they are never scoped.
- Slug = lower-kebab of the file stem; collisions get a deterministic `-2`, `-3` suffix in source order.
- Provenance: every generated file starts with `<!-- generated by scripts/mdc_convert.py from <source> sha256=… -->`; managed blocks carry the same info in their `begin` marker. `.claude/mdc-manifest.json` lists every rule, its type, target, and hash.

## Usage

```bash
cd /Users/machine/apps/IoT-ASP
make mdc                         # or: python3 scripts/mdc_convert.py
python3 scripts/mdc_convert.py --dry-run          # plan only
python3 scripts/mdc_convert.py --check            # CI gate (exit 1 when outputs are stale)
python3 scripts/mdc_convert.py --src ../.cursor/rules   # also pull shared rules from apps/
python3 scripts/mdc_convert.py --json             # machine-readable plan
```

Idempotent: a second run is a no-op, `--check` passes, and text outside the markers in `CLAUDE.md` /
`SPEC.md` is preserved. Deleting a `.mdc` prunes its generated rule/skill/block on the next run; hand-written
files in `.claude/rules/` (no provenance comment) are never touched.

## Config (`.mdc-convert.json`)

```json
{
  "sources": [".cursor/rules"],
  "legacy_cursorrules": true,
  "claude_file": "CLAUDE.md",
  "spec_file": "SPEC.md",
  "rules_dir": ".claude/rules",
  "skills_dir": ".claude/skills",
  "manifest": ".claude/mdc-manifest.json",
  "agent_requested_as": "skill",
  "spec": ["asp-prior-art"],
  "map": {"some-rule": "rule"}
}
```

## On the Mac (where the `.mdc` files live)

The `.mdc` files were never pushed to `origin`, so this repo's `main` contains none. On the Mac clone:

```bash
cd /Users/machine/apps/IoT-ASP
git pull
python3 scripts/mdc_convert.py            # converts .cursor/rules/*.mdc (and ../.cursor/rules with --src)
git add .cursor/rules CLAUDE.md SPEC.md .claude && git commit -m "Convert Cursor rules to Claude Code memory"
```

Commit the `.mdc` sources too; CI (`mdc check` job) then guarantees the generated outputs never drift.
